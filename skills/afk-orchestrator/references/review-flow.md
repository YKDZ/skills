# 审查、修复与最终审计

在 B/C 候选进入只读证明或独立审查、出现已接受必修问题或所有切片完成时读取。

## 候选审查

实施行动同时交付生产修改、全部计划内测试与必要探针，并在提交候选前运行成功。编排者据此固定不含范围外修改的不可变候选。约定失败模式证明时，证明行动只读检查该候选；受控变异优先在隔离副本中进行，若临时修改当前工作树，结束前必须证明工作树已精确恢复到候选指针所指状态。

证明行动发现产品缺陷时报告 `INCOMPLETE`，保留原候选和反例。该反例作为实施证据处理，不列为审查必修问题。编排者可以在现有授权内派发实施行动，修复后形成新候选并重新完成约定证明。反例推翻已接受设计时形成设计事件。约定的证明通过后才派独立审查。A 类只运行确定性门禁；B 类派合同审查；C 类对同一候选分别派合同审查和失败模式审查。

`afk-slice-reviewer` 按其判定规则给出审查报告中的必修问题。编排者核对每项问题的候选、合同和证据指针；材料一致的问题进入候选修复合同，材料不一致时记录拒绝理由。设计机制、共享不变量或所有权被推翻时形成设计事件。

首轮审查在一次调用内完成消息所分配焦点的覆盖，并汇总当前证据可确认的全部必修问题；发现首个问题不结束审查。无法完成约定合同、生产接缝或失败类别的覆盖时报告 `INCOMPLETE`，并列出未覆盖项。`COVERAGE` 留有约定未覆盖项时，编排者按 `INCOMPLETE` 处理，不受结果字段影响。

同一不可变候选和审查焦点已有完整结论时不重复审查。修复候选只走一条复核路径：

- 原审查均已完成，且已接受设计、合同、生产接缝和范围未变：做一次关闭复核
- 上述边界未变，但有完整审查未结束：只重新完成未结束的焦点
- 已接受设计、合同、生产接缝或范围发生变化：重新完成该路由要求的全部完整审查

重开的完整审查同时核验已接受必修问题、受影响合同和修复增量，不再追加关闭复核。未重开的完整审查结论，由本次复核对修复增量的核验承接到新候选。

## 候选修复与关闭复核

候选修复按公共契约提供原候选、父合同、精确问题、可写范围和必须重证的条目，并要求执行者读取自己的修复参考。新候选重新完成该切片约定的只读证明后，按上节选择复核路径。关闭复核使用待关闭问题来源中的最高档位，只检查：

- 已接受必修问题是否关闭
- 受影响合同是否重新获得证据
- 修复增量是否引入合同或不变量回归

关闭复核保持上述焦点。返回 `CHANGES_REQUIRED` 时固定新反例，当前候选保持未验收；编排者依据合同和已有证据选择后续行动。

## 门禁节奏

- 实施与候选修复运行切片级测试、类型检查和生产边界验证
- 根门禁只在整合里程碑、共享基础设施变化或最终候选上运行
- 发布产物、真实权限、真实认证、跨进程或恢复语义必须从相应生产入口证明

## 最终审计

所有切片完成后，只审计跨切片接缝、共享不变量、未在切片层证明的生产边界和整合回归。非 C 风险使用 t1；仍有 C 类审计面时使用 t2。最后一次整合后的成功根门禁可以同时充当最终门禁，不重复执行。
