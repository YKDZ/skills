# 审查、修复与最终审计

在 B/C 候选进入只读证明或独立审查、出现已接受必修问题或所有切片完成时读取。

## 候选审查

实施行动同时交付生产修改、全部计划内测试与必要探针，并在提交工作结果前运行成功。编排者据此固定不含范围外修改的不可变候选。约定失败模式证明时，证明行动只读检查该候选；受控变异优先在隔离副本中进行，若临时修改当前工作树，结束前必须证明工作树已精确恢复到候选指针所指状态。

证明行动发现产品或验收工具缺陷时报告 `INCOMPLETE`，保留原候选和反例，交回编排者安排实施。局部工具修复留在原切片，在授权范围内完成后固定新候选，按下文复用证据。反例推翻已批准结果所需的设计机制时形成设计事件。

A 类只运行确定性门禁；B 类派合同审查；C 类对同一候选分别派合同审查和失败模式审查。只读证明与不依赖其结果的独立审查可以并行，使用同一不可变候选且运行资源互不干扰；验收前仍须补齐约定证明与审查。

`afk-slice-reviewer` 按其判定规则给出审查报告。编排者核对每项问题的候选、合同和证据指针，按[验收合同](../SKILL.md#验收合同)判断是否采纳，再纳入候选修复合同；不采纳时记录理由。

审查返回 `DESIGN_EVENT` 时按前述设计事件处理；其他结果的 `COVERAGE` 留有约定未覆盖项时，编排者按 `INCOMPLETE` 处理。

同一不可变候选和审查焦点已有完整结论时不重复审查。修复形成新候选后，分别处理路由要求的审查焦点：

- 前次未完成的焦点在新候选上补完
- 因已接受设计、合同、生产接缝或范围变化而失效的焦点重新完整审查
- 其余完整结论继续有效

补完或重审同时核验本焦点产生的已接受必修问题与修复增量，不再追加同焦点关闭复核。其余已接受问题和未被这些审查覆盖的修复增量统一做一次关闭复核。一个焦点的复核不能替代另一个未完成或已经失效的焦点。

## 修复、证据复用与关闭复核

候选或验证方法变化后，编排者对照产品、断言、输入和环境的变化，保留仍适用的证据，列明必须重证的条目及原因。复用证据保留原候选和运行条件，不记为本轮执行。明确要求同一实例、同一轮次或完整状态序列的结果，仍须按该要求完整验证。

派发修复时，以受影响的父级合同和预期结果界定任务，附原候选、可重放的原反例、可写范围和必须重证的条目，并要求执行者读取修复参考。

编排者接收新候选前，对照实际入口核对关闭证据，确认原反例的触发条件仍被覆盖；涉及共享接口时，核对调用方是否已同步修改。关闭复核只检查：

- 已接受必修问题是否关闭
- 受影响合同是否重新获得证据
- 修复增量是否引入合同或不变量回归

关闭复核保持上述焦点。返回 `CHANGES_REQUIRED` 时固定新反例，当前候选保持未验收；编排者依据合同和已有证据选择后续行动。

## 门禁节奏

- 实施与候选修复运行切片级测试、类型检查和生产边界验证
- 根门禁只在整合里程碑、共享基础设施变化或最终候选上运行
- 最终根门禁在候选固定、会争用相同运行资源的行动结束且已清理其资源后运行
- 发布产物、真实权限、真实认证、跨进程或恢复语义必须从相应生产入口证明

## 最终审计

所有切片完成后，只审计跨切片接缝、共享不变量、未在切片层证明的生产边界和整合回归，沿用上述必修判定与采纳规则。非 C 风险使用 t1；仍有 C 类审计面时使用 t2。最后一次整合后的成功根门禁可以同时充当最终门禁，不重复执行。
