# 审查、返工与最终审计

在 B/C 候选进入审查、出现已接受阻塞项或所有切片完成时读取。

## 候选审查

审查前先逐项核对合同，并物化不含范围外修改的不可变候选。A 类只运行确定性门禁；B 类派一次合同审查；C 类对同一候选分别派合同审查和失败模式审查。

问题项是否构成 `BLOCKER`，以 `afk-slice-reviewer` 的问题项判定为唯一权威定义。编排者接受或拒绝每项问题并记录理由；只有已接受的阻塞项进入返工合同。设计机制、共享不变量或所有权被推翻时形成设计事件，不进入普通返工。

## 返工与关闭复核

已接受阻塞项只触发一次有界返工。返工消息按公共契约提供原候选、父合同、精确问题项、可写范围和必须重证的条目，并要求执行者读取自己的返工参考。

返工后派一个新的只读关闭复核，只检查：

- 已接受阻塞项是否关闭
- 受影响合同是否重新获得证据
- 返工增量是否引入合同或不变量回归

关闭复核不得重新进行开放式搜索。复核后仍有阻塞项就停止循环，在设计事件、重新切片和 `INCOMPLETE` 之间裁决。

## 门禁节奏

- 实施与返工运行切片级测试、类型检查和生产边界验证
- 根门禁只在整合里程碑、共享基础设施变化或最终候选上运行
- 发布产物、真实权限、真实认证、跨进程或恢复语义必须从相应生产入口证明

## 最终审计

所有切片完成后，只审计跨切片接缝、共享不变量、未在切片层证明的生产边界和整合回归。非 C 风险使用 t1；仍有 C 类审计面时使用 t2。最后一次整合后的成功根门禁可以同时充当最终门禁，不重复执行。
