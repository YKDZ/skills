# C 类设计与原型

只在路由为 C 时读取。目标是先关闭实施者不能自行决定的生产语义，再派正式实施。

## 设计派发

设计消息在公共契约上追加：

- 要关闭的所有权、状态转移、接口、数据、恢复、权限或外部系统语义
- 共享设计文档路径、适用任务单和非目标
- 每项关键不变量的生产接缝、反例或观察方式
- 实施者可以自行决定的可逆细节，以及不得重新决定的单向门
- 原型许可：不允许，或允许一个并给出授权来源和有限探索问题

设计文档服务于共享机制，不按任务单复制，也不是逐文件施工说明。仍有问题会迫使实施者发明生产语义时，设计保持 `INCOMPLETE`。

## 原型许可

默认不允许原型。只有静态材料无法关闭一个明确设计决策时，才允许一个原型，并在消息中写明：

- 类型、单一假设或最小人类选择问题
- 反证观察、判定阈值和将解锁的设计决策
- 有限的状态、动作、实验或方案数量
- 独立工作区、允许操作和临时资源

详细类型、观察格式、保留方式和清理生命周期以 `afk-slice-worker` 的设计文档契约为唯一权威定义。编排者不在消息中重新解释这些规则。

客观探针得到结论并完成清理后才能提交设计候选。视觉方案只提交 `READY_FOR_HUMAN`；人类决定写回权威设计、保留资源完成清理后，才可继续实施。

## 设计接受

接受设计前确认：

- 关键生产语义和失败模式已经关闭
- 每个不变量都有可执行证明方式
- 原型结论已进入设计和允许的 `docs/observations/`
- 没有原型代码或资源污染正式候选

设计被接受后，实施消息只引用设计指针和不得重新决定的语义，不复制整份设计。
