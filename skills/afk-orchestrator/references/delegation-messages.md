# 公共派发契约

派发消息只描述当前行动。事实材料使用路径和提交指针，不复制完整文档，不继承前序代理结论。

## 公共字段

每条消息必须明确：

- 可观察结果与当前行动
- 权威来源及冲突时的优先顺序
- 固定点；审查时还包括不可变候选
- 可写、保持与排除范围
- 验收合同及生产接缝或反例
- 当前行动要运行的门禁
- 本次尝试边界、停止条件和完成报告

风险路由、模型档位、实际运行配置、隔离工具和宿主遥测由编排者及宿主适配层处理。只有它们会改变接收者行为时才写入消息。

## 公共消息骨架

```text
调用 <afk-slice-worker | afk-slice-reviewer> 完成一个有界行动：<设计、实施、返工、清理或审查的可观察结果>。

权威依据：<任务单 / 规格 / 架构决策记录 / 已接受设计 / 前置提交 / 代码入口 / 相关观察指针>。冲突时以 <来源> 为准。
固定点：<提交>。候选：<审查时填写不可变候选；其他行动省略>。
范围：<可写位置或只读范围>；必须保持 <不变量>；排除 <相邻工作>。
验收合同：<ID / 义务 / 生产接缝或反例 / 所需证据>。
当前门禁：<针对性测试、类型检查或生产边界验证>。
本次尝试：<初始行动 | 唯一允许的单证据续派 | 不续派>。

证据齐全时提交候选报告；无法安全完成时交回已形成证据、未决合同条目和唯一下一证据。不得扩大范围或自行开启新会话。
```

只有实施与返工需要可写范围；设计通常只写设计文档与允许的观察，审查只读。

## 条件增量

不要复制新的完整模板，只在公共骨架后追加当前行动需要的字段。

| 触发条件 | 追加内容 |
| --- | --- |
| B 类实施 | 内联机制简案：所有权、接缝和关键失败模式 |
| C 类设计 | 按 [C 类设计与原型](c-design.md) 追加设计问题、产物路径和原型许可 |
| C 类实施 | 已接受设计指针，以及实施者不得重新决定的生产语义 |
| 合同或失败模式审查 | 审查焦点、已有证据和明确排除项 |
| 已接受阻塞项返工 | 阻塞项、父合同、返工前候选和必须重证的条目 |
| 关闭复核 | 原候选、返工候选、已接受阻塞项及受影响合同 |
| 原型清理 | 原型生命周期记录、精确资源和清理触发条件 |
| 唯一续派 | 单个证据缺口、当前可复现事实、禁止重复的探索和预期证据增量 |

返工、关闭复核和最终审计的范围由 [审查、返工与最终审计](review-flow.md) 定义。原型类型与生命周期由 `afk-slice-worker` 的设计文档契约定义。

## 可选能力

只有派发消息明确要求且宿主支持时才使用持久任务机制。任务目标覆盖整个切片的可观察结果、范围和完成条件；持久任务状态不能代替合同证据。

软时间检查点默认不存在。启用前必须读取 [软时间检查点](checkpoint.md)，并把来源、指标、阈值、计量方式和到点行为完整写入消息；未启用时省略整个字段，不写 `unset`。

具体模型、宿主产品和派发参数不得写入本参考。
