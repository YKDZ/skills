# 公共派发契约

派发消息只描述当前行动。事实材料使用路径和提交指针；前序结论通过持久材料提供。

## 公共消息骨架

按以下骨架明确当前行动。风险路由、模型档位、实际运行配置、隔离工具和宿主遥测只有会改变接收者行为时才写入消息。

```text
调用 <afk-slice-worker | afk-slice-reviewer> 完成一个有界行动：<设计、实施、修复、清理或审查的可观察结果>。

权威依据：<任务单 / 规格 / 架构决策记录 / 已接受设计 / 前置提交 / 代码入口 / 相关观察指针>。冲突时以 <来源> 为准。
固定点：<提交>。候选：<只读证明或审查时填写不可变候选；其他行动省略>。
范围：<可写位置或只读范围>；必须保持 <不变量>；排除 <相邻工作>。
验收合同：<ID / 义务 / 生产接缝或反例 / 所需证据>。
当前门禁：<针对性测试、类型检查或生产边界验证>。
已有证据：<相关调查、观察、反例、候选和已排除路径的指针>。
证据目标：<当前未决合同义务，以及本行动应形成的可证伪证据>。
行动边界：<依赖、读写所有权和停止条件；相关时说明会影响观察结果的共享运行资源、释放条件和清理责任>。

证据齐全时提交完成报告；命中行动边界中列出的停止条件时，明确引用该条件并交回已形成证据和未决合同条目。其余计划内工作继续当前行动；消息要求使用 Goal 时保持同一 Goal 进行中。不得扩大范围或自行开启新会话。
```

可观察结果、合同、生产接缝、门禁和可写范围共同构成行动开始时的固定边界。

不可变候选指针至少在相关验收或显式清理前必须能重新取回精确内容。单独的差异摘要或内容摘要只能用于核对一致性。快照载体必须落在消息的可写范围和版本控制授权内；使用 Git 提交需要消息明确允许。

实施与修复需要产品代码可写范围；设计只写消息允许的设计文档、观察或原型资源，审查只读。

## 条件增量

不要复制新的完整模板，只在公共骨架后追加当前行动需要的字段。

| 触发条件 | 追加内容 |
| --- | --- |
| B 类实施 | 内联机制简案：所有权、接缝和关键失败模式 |
| C 类设计 | 按 [C 类设计与原型](c-design.md) 追加设计问题、产物路径和原型许可 |
| C 类实施 | 已接受设计指针，以及实施者不得重新决定的生产语义 |
| 合同或失败模式审查 | 审查焦点、已有证据和明确排除项 |
| 重开的完整审查 | 已接受必修问题、受影响合同和修复增量 |
| 候选修复 | 已接受必修问题、父合同、修复前候选和必须重证的条目 |
| 关闭复核 | 原候选、修复候选、已接受必修问题及受影响合同 |
| 原型清理 | 原型生命周期记录、精确资源和清理触发条件 |

候选修复、关闭复核和最终审计的范围由 [审查、修复与最终审计](review-flow.md) 定义。原型类型与生命周期由 `afk-slice-worker` 的设计文档契约定义。

## Goal 与时间检查点

实施与候选修复消息必须明确要求接收者创建 Goal。Goal 覆盖当前行动的可观察结果、固定边界、停止条件和完成证据；在公共骨架规定的有效完成报告形成前保持进行中，普通轮次结束后继续同一 Goal，只有有效完成报告形成后才标记为 `complete`。消息必须要求 `INCOMPLETE` 引用具体的边界变化或停止条件。其他行动只在消息明确要求时使用 Goal。Goal 状态不能代替合同证据。

软时间检查点默认不存在。启用前必须读取 [软时间检查点](checkpoint.md)，并把来源、指标、阈值、计量方式和到点行为完整写入消息；未启用时省略整个字段，不写 `unset`。

具体模型、宿主产品和派发参数不得写入本参考。
