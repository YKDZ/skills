# Subagent 消息构造参考

以下内容按任务增删。任务边界在消息内自包含，事实材料通过上下文指针提供，不规定 subagent 的具体实现步骤。

## Goal 决策

派发前先判断切片是否预计跨多个会话轮次、包含多项完成证据，并且能在当前权限内持续推进。三项都成立时，把下面这句话放在初始消息开头，让创建 goal 成为第一项动作：

```text
立即为本消息定义的有界结果创建 goal，将可观察结果、范围和验证条件写入 objective；验证条件未全部满足前保持 active。不要设置 token_budget。
```

单轮工作和可能立即等待外部输入的工作不创建 goal。Goal 保持任务持续运行，不能代替清晰边界、因果测试和独立审查。编排者仍需检查每次续派的证据增量。

## 任务契约

一条实施消息应让接收者无需继承完整会话也能回答：

1. 要产生什么可观察结果？
2. 哪些 ticket、Spec、ADR、研究笔记、前置提交与代码入口是原始依据？冲突时以哪个为准？
3. 哪个实际边界必须成立：源码、进程、真实认证、候选产物、发布产物或外部系统？
4. 哪些行为或性质不能被破坏？哪些相邻工作不在范围内？
5. 阶段固定点是什么？当前会话可以写哪些文件或模块？
6. 哪个测试应先失败？失败原因如何证明它命中了目标机制？
7. 当前切片运行哪些针对性门禁？哪些后续验收不属于本切片？
8. 哪些证据齐全才可报告完成？出现什么情况必须停止并报告？

上下文指针与边界字段共同构成自包含消息：接收者无需继承完整会话就能定位事实并开始工作。优先给出原始材料和可运行入口的路径或提交，让 subagent 自行读取；不复制已有内容，不转述完整历史，不把上一位 agent 的结论当成事实。

满足边界并给出证据时报告 `COMPLETE`。其余情况报告 `INCOMPLETE`、已完成部分、缺失证据与最小下一步。

## 实施切片

```text
调用 afk-slice-worker 实现 <ticket> 的一个纵向切片：<可观察结果>。

原始依据：<ticket / Spec / ADR / 研究笔记 / 前置提交 / 代码入口的指针>。冲突时以 <权威来源> 为准。
阶段固定点：<提交>。
可写范围：<文件或模块>。
必须证明的生产边界：<真实进程、权限、候选产物等>。
保持：<不变量>。
范围外：<相邻工作>。

优先建立一个在当前实现上因 <缺失机制> 而失败的因果测试，再完成最小实现。
当前切片运行：<针对性门禁>。阶段完整门禁和独立审查不属于本切片。

档位：<T1 或 T2>。若发现 <升级条件>，停止扩大范围并报告 INCOMPLETE。
只有 <证据清单> 全部成立才报告 COMPLETE。
```

## 继续同一切片

继续消息只处理一个缺口，并指出预期证据增量：

```text
继续当前切片，只处理 <一个缺口>。
当前可复现事实：<证据>。
不要重复：<已完成探索>。
先让 <回归测试> 因该缺口失败，再修复并运行 <针对性门禁>。
预期证据增量：<新变更、新 RED/GREEN 或待排除假设>。
完成协议仍为 COMPLETE/INCOMPLETE；范围保持为 <可写边界>。
```

连续两次续派没有形成证据增量时，不再复用该会话。

## 审查返工

返工消息只发送原始需求、问题项记录和返工允许修改的范围：

```text
调用 afk-slice-worker 返工 <范围>。
固定点：<返工前提交>。
需要关闭：<问题 ID、事实、严重度、因果反例>。
可写范围：<文件或模块>。
保持：<不变量与非目标>。

逐项复现问题，完成最小修复，并运行 <针对性门禁>。
报告每项问题的关闭证据和本次增量。
任一问题未关闭或边界门禁无法执行时报告 INCOMPLETE。
```
