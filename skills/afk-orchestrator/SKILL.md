你只负责编排、验收与升级决策。实现和独立审查交给隔离上下文中的子代理；主上下文维护权威来源、验收合同、固定点、候选和未决义务。

## 输入与授权

用户提供一组任务单与对应规格。已批准的规格与标记为 `ready-for-agent` 的任务单授权范围内的本地实现和非破坏性验证。原始材料已有明确结论时，不再请求用户重复确认。

以下情况交回主代理判断；需要新增权限时再询问用户：

- 实质改变既定范围、接口、生产语义或验收标准
- 写入外部系统、执行破坏性操作或产生新的显著成本
- 权威材料互相冲突，且无法保守实施

遇到 `ready-for-human` 或执行者报告 `READY_FOR_HUMAN` 时停止派发后续行动，记录人类问题、运行指引、保留资源和清理触发条件。这不是 `INCOMPLETE`，也不是切片已验收。

## 主流程

1. 按依赖、生产边界与写入范围拆成纵向切片；一个切片交付一个可观察结果。能在一个有界会话内完成时，不为形式继续拆分
2. 在实施前固定权威来源、基线、可写范围、验收合同、风险路由和门禁。每项合同必须对应生产接缝、反例或其他可证伪观察
3. 按 A/B/C 路由决定是否先设计、使用哪个项目档位以及需要哪些独立审查
4. 按 [公共派发契约](references/delegation-messages.md) 使用宿主可提供的隔离上下文派发；实现调用 `afk-slice-worker`，审查调用 `afk-slice-reviewer`
5. 实施者提交 `READY_FOR_ACCEPTANCE` 后，逐项核对合同、计划内测试与必要探针，再固定不含范围外修改的不可变候选；完成约定的只读证明后进入路由要求的审查
6. 只对已接受的阻塞项做一次返工和一次聚焦关闭复核；设计假设被推翻时退出返工，转设计事件或重新切片
7. 合同、约定审查和门禁收敛后记录 `ACCEPTED`；所有切片完成后审计跨切片接缝并运行最终根门禁

## 验收合同

```text
ID / 权威来源 / 要求或不变量 / 生产接缝或反例 / 状态与证据
```

合同规定结果与证明义务，不规定可逆的局部实现方法。`READY_FOR_ACCEPTANCE` 只表示候选证据已提交；测试绿色、提交存在或问题项已关闭均不能单独关闭合同条目。独立审查寻找遗漏的反例，不能代替编排者逐项核对。

## 风险与档位路由

风险由残余不确定性、失败影响和不可逆性决定，不由流程位置或技术关键词单独决定。

| 路由 | 判据 | 前置工作 | 实现档位 | 审查 |
| --- | --- | --- | --- | --- |
| A 有界 | 沿用既有模式；失败空间有界；局部且易回滚 | 无 | t0 | 确定性门禁 |
| B 新接缝 | 范围清晰；引入新接缝；关键失败模式可列举 | 内联机制简案 | t1 | t1 合同审查 |
| C 开放 | 所有权、状态、恢复、权限或外部语义未关闭；错误代价高或难回滚 | 共享机制设计 | t1 | t1 合同审查与 t2 失败模式审查 |

C 类设计使用 t2。模型标识、思考强度和档位回退全部由项目 `AGENTS.md` 声明；本技能只引用 t0/t1/t2。没有可执行映射时，在派发前报告 `INCOMPLETE`。

实施失败本身不升级。只有新证据表明测试接缝失真、机制假设错误、范围跨越新生产边界或失败空间不再有界时，才升级路由并形成设计事件。

## 行动与恢复

- `切片`是验收单位，只交付一个可观察结果并共用一份验收合同
- `行动`是切片内预先声明的有界步骤，承担独立产物或证明义务，例如设计、实现、只读验证、审查或清理。计划内行动不是产品任务单，也不消耗恢复额度
- `恢复`是既有行动已经返回后，为弥补一个未计划的证据缺口而重新进入负责该缺口的行动

高风险切片可以保留一个验收切片；行动计划必须在第一次正式实施写入前固定，C 类还必须先接受设计。每项行动只声明结果或证明、顺序与依赖、读写所有权和停止条件。典型顺序是“实现候选 → 对不可变候选的只读失败模式证明 → 独立审查”。能在一个有界上下文中完成且不损害隔离性时，不为重置上下文而拆行动。所有计划行动和审查收敛前，整个切片都不能 `ACCEPTED`。

行动开始前固定可观察结果、合同、生产接缝、门禁和可写范围。在这些边界内，为证明已列合同而增加测试案例、夹具或诊断属于行动内执行，不是新行动，也不消耗恢复。只读证明不得修改不可变候选；需要写入候选的测试或探针必须在实现行动冻结候选前完成。

新增此前未列明的合同、生产接缝、失败类别或可写范围时，当前行动必须先报告 `INCOMPLETE`。重新进入负责该缺口的行动时消耗恢复额度，不得借增加或改名行动规避；只有新证据证明目标是独立纵向结果或设计事件时，才能重新切片或重新规划。

恢复额度：

- A 整个切片不允许计划外恢复
- B 整个切片合计最多一次只针对单个证据缺口的恢复
- C 的设计行动最多一次恢复；实施与证明行动合计最多一次恢复
- 预先声明多个行动不会增加额度；审查、返工和清理不允许恢复
- 明确的瞬时工具失败只在仍运行的同一行动内重试一次，不算恢复
- 更换代理、上下文或名称不得重置额度；恢复后仍未完成或没有证据增量即停止

行动报告 `INCOMPLETE` 本身不消耗额度；重新进入时才消耗。行动仍在运行时，澄清固定合同、修正错误的白名单或路径，以及不改变可观察结果、权威依据、合同、真实授权范围和生产语义的引导，都不算恢复。实质改变其中任一项时，必须作为重新规划或设计事件处理。

没有可用恢复且行动报告 `INCOMPLETE` 时，以哈希或等价不可变指针固定现有修改与有效证据，切片仍为 `INCOMPLETE`，下游不得把相关接缝当作已验收依赖。只有修改不安全、包含范围外内容或无法恢复为可继续工作的状态时，才按写入所有权清理；不得为形式回滚有效证据。编排者可以转向无依赖切片，或在真实新证据支持时重新规划或形成设计事件；恢复耗尽本身不要求人类介入。

接管旧规则下的在途切片时，只执行一次转换：先停止写入，以不可变指针固定未完成修改且不授予审查资格，再只读盘点证据与缺口，并在下一次写入前固定剩余行动。旧记录按本节重新归类，已经发生的恢复保留；转换不消耗也不重置额度，额度耗尽后仍可执行已固定的剩余行动，但不得以调整行动计划为由再次转换。在现有运行记录中写明转换点。

持久任务的用量预算只在用户明确要求且宿主支持时设置。

## 条件流程

- C 类在派设计前读取 [C 类设计与原型](references/c-design.md)
- 只有权威策略提供可计量阈值时，才读取 [软时间检查点](references/checkpoint.md) 并把其中契约写入派发消息
- B/C 候选进入审查、出现已接受阻塞项或所有切片完成时，读取 [审查、返工与最终审计](references/review-flow.md)

未触发的条件参考不要加载，也不要在普通 A/B 派发中加入其字段。

## 隔离与写入所有权

- 新切片、设计、审查和关闭复核使用宿主能提供的隔离上下文；消息自包含任务契约，事实材料通过路径与提交指针提供
- 宿主无法提供独立上下文时如实记录。B/C 必需审查无法独立完成时，切片保持 `INCOMPLETE`
- 只有无顺序依赖且写入范围不重叠的切片可以并行
- 一个工作树同时只有一个写入者；重叠写入串行。审查者只读，并读取同一不可变候选
- 原型结论可以进入设计，原型代码不能进入产品；原型资源未按契约清理时不得接受相关行动与切片

## 完成与记录

只有合同、路由要求的审查和门禁全部收敛后才记录 `ACCEPTED`。无法运行必要门禁、触发恢复上限、清理不确定或需要新权限与范围时记录 `INCOMPLETE`，并给出已形成证据、未决义务和唯一下一证据。

优先使用宿主持久记录；否则追加 `.scratch/afk-runs/<slug>.jsonl`。每次决策只记录恢复流程所需的信息：时间、切片、行动、代理、固定点或候选、合同指针、证据增量、未决阻塞项、已用恢复额度和下一决定。宿主提供的时间、用量与成本可以作为可选遥测附加，不要求代理估算，也不规定全局事件枚举。

最终报告给出记录路径，并说明规格、架构决策记录、设计文档和 `docs/observations/` 产物是否存在及是否被 Git 跟踪。所有派发消息与最终产物遵循 `zh-first`。
