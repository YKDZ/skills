# 票图管理

## 接入

用户为选定票集明确启用后接入。后续会话从项目既有票据约定找到配置和工具入口，沿用已启用的范围。

入口是本技能目录下的 `scripts/ticket-graph.mjs`，用 `node` 运行，传入 `--help` 阅读帮助。根命令及各子命令的帮助提供命令参数、配置和票据格式、输出约定及示例；未配置票集时也可阅读。取得完整技能目录并具备 Node.js 即可运行。

首次接入用 `init` 创建票集配置，已有配置直接沿用。`tickets` 指向票目录，`completion.values` 指定表示交付完成的状态值；票头固定使用 `status`。相对路径以配置所在目录为基准，调用时通过 `--config` 显式选择票集。复用项目已有的完成约定；交付完成表示票约定的交付已具备，后继票可以据此继续实施。

配置可直接编辑，每次使用均会校验；修改格式时查阅[配置结构定义](ticket-graph.schema.json)。`init` 只创建配置，票图是否有效仍由 `check` 判断。

接入旧票前，对照帮助说明现有格式的差异，只迁移必要的机器字段。旧配置移除 `completion.field`，原状态字段迁移为 `status`；状态和依赖集中在 YAML 文件头，正文保留任务内容。新票创建和首次接入可直接写入初值；整理后检查票图，并在项目既有票据约定中记录配置位置、工具入口及机器字段的编辑约定。

## 使用

各票文件是当前数据的唯一依据。保持票标识稳定，直接编辑正文时保留机器字段，并与同票的命令写入错开。接入后的状态和依赖变更通过工具完成；字段损坏导致工具无法读取时，先做保留原值的最小格式修复，再重新检查。

按帮助选择结构检查、当前数据查询、状态修改、依赖替换或历史查询。可逐票修复已有问题，依据结果处理剩余错误；一次修改成功仍可能留有其他结构问题。

依赖已满足的未完成票只是候选，查询仅反映已登记的依赖与完成情况。调用者继续判断需求覆盖、依赖完整性、优先级、在途工作、人类介入及交付验收，并自行安排实施。

旁置历史记录通过工具完成的元数据变更，仅供追溯；查询当前票图仍以票文件为准。命令失败时，先核对报告中的已写入部分与不确定结果，保留必要证据后决定下一步，避免直接重试或回滚。查询失败也不能按空结果处理。
