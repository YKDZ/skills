# 票图管理

## 接入

用户明确启用选定票集后使用。先核对项目既有票据约定。

用 Node.js 24.12 及以上版本运行[工具入口](scripts/ticket-graph.mts)，先查看根命令及相关子命令的 `--help`。命令用法以帮助为准；需要直接编辑配置时，参考[配置结构定义](ticket-graph.schema.json)。

沿用已有配置；缺少配置时通过工具初始化，票目录和完成值由项目约定。接入后检查票图结构，将配置位置和工具入口记入项目既有票据约定，供后续会话沿用。

## 工作判断

调用者依据原始需求和实际证据决定工作范围、优先级、派发与验收。工具检查已声明的结构，无法判断需求是否覆盖、依赖是否遗漏或交付是否属实。交付完成表示本票约定的交付已具备，后继票可以据此继续实施。

- 查询显示前置已满足，仅说明已登记的直接前置票均被标记完成，不限定派发顺序或工作范围。
- 前置尚未满足的票，也可以推进不依赖缺失交付的独立部分；需要该交付的部分仍须等待。
- 发现已标记完成的票仍有本票约定内的工作未完成时，通过工具改回项目适用的未完成状态，并核对受影响的后继票。状态按事实修正。

## 数据维护

票文件是当前数据的唯一依据。历史只记录工具执行的变更，供追溯使用。文件名的数字前缀提供标识，如 `01-任务标题.md`；建票后保持标识稳定。文件开头使用以下 YAML 票头，正文自由编写：

```yaml
---
status: "<项目约定的状态值>"
blocked_by: []
---
```

两个字段必填。将状态占位符替换为项目约定的非空状态值；依赖使用带引号的数字字符串，保留前导零，如 `["02", "003"]`；无依赖使用 `[]`。

创建票时可直接写入初值，此后的状态和依赖变更通过工具完成。同票的正文编辑与命令写入错开，并保留机器字段。

字段损坏导致工具无法读取时，先做保留原值的最小格式修复，再检查。结构问题可逐票修复；一次修改成功不表示其他问题也已解决。

修改失败时，先核对返回结果与实际写入的票文件和历史，再决定是否重试或继续修复；已保存的修改仍然有效。查询失败不能当作没有待办工作。
