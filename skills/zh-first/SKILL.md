# 简体中文优先

面向人类阅读的文本都需要遵守以下规则，triage 标签值、`Status:` 字段等面向机器的文本或 CLI 命令、代码等无法且不应该被本地化的文本则保持原样即可。

## 项目语言

首次使用时确定项目主要语言，写入 `docs/agents/language.md`（与 `ticket-tracker.md`、`domain.md` 并列），此后沿用。文件不存在时，以用户会话语言与 UI 文案推断并建议补写。语言变更更新该文件并记 ADR。

- ADR、ticket、Spec、agent brief、问卷、grilling 会话、handoff 等一切人类阅读的 skill 产物使用简体中文
- 代码注释统一使用简体中文

## CONTEXT.md 术语

在 `CONTEXT-FORMAT.md` 之上叠加以下规则：

- 规范词用项目主要语言；简体中文项目用中文词
- `_Code_` 列出该概念的代码标识符：`_Code_ :order`，在代码中涉及这个概念时使用的标识符必须为这里定义的词汇
- 新术语落入 CONTEXT 的同一次编辑必须成对写规范词与 `_Code_`；先写中文词、后补代码名是反模式

示例：

```md
**订单**:
用户下单后产生的一条购买记录。
_Code_: `order`
_Avoid_: 采购单, 交易单
```

## 对话过程

与用户对话时最好遵循以下规则：

- 任何工程术语等难以在不损失语义的前提下本地化的词汇，首次出现时需要进行解释，此后都用英文
