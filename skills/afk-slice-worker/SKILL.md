name: afk-slice-worker
description: AFK 切片执行，在给定边界与预算内完成一个设计、实现或返工切片并返回证据
---

完成当前消息定义的一个有界切片。只使用消息明确提供的信息和可读取的工作区材料；没有出现的信息视为未知。

若任务要求规划整组 ticket、派发 agent、执行独立审查或负责整体交付，报告 `INCOMPLETE` 并说明它不属于本技能。不要自行扩大角色。

## 开始前

读取指定的 ticket、Spec、ADR、已接受设计与代码入口，以原始材料为准。确认以下内容明确：

- 可观察结果、风险路由和 active-time 护栏
- 阶段固定点、可写文件或模块
- 验收合同、生产边界、针对性门禁与完成证据
- 必须保持的不变量、范围外工作和升级条件

关键边界缺失且无法从权威材料确定时报告 `INCOMPLETE`，列出缺失项和最小下一步。不要把猜测固化为实现。

派发消息要求使用宿主持久任务机制时，让目标覆盖整个切片的可观察结果、范围和完成条件。宿主不提供或消息未要求时省略；用量预算只在用户明确要求且宿主支持时设置。持久任务状态不能代替完成证据。

达到 active-time 护栏时停止新增探索，保留工作区，报告 checkpoint、已形成证据、未决假设和最小下一步。护栏到期不能把未证明事项标成完成。

## 设计切片

被派发 C 类设计时，读取 [设计文档契约](references/design-brief.md)，按共享机制而非单 ticket 产出设计。设计必须关闭会迫使实施者决定生产语义的问题；无法关闭时报告 `INCOMPLETE`。

只有机制不确定性值得通过可执行实验消除时才调用 `prototype` skill。原型一次性、不得进入产品。若设计或实现依赖环境事实，读取并遵循 [观察账本契约](references/observations.md)。

## 实施

- 检查阶段固定点，建立能直接解释目标机制的失败证据
- 存在稳定且有意义的测试接缝时调用 `tdd` skill，记录 RED 后完成最小实现并记录 GREEN；否则选择最接近生产边界的可重复证据
- 只修改允许范围。正确实现需要新的 ownership、接口、状态语义或生产边界时，停止并报告升级理由
- 运行当前消息要求的测试、类型检查与边界验证；除非明确要求，不运行完整根门禁，也不提交代码
- 收尾时逐项核对验收合同，并检查范围外修改

修改持久状态机、恢复协议或可重入跨进程生命周期时，列出范围内持久状态与可中断转换。从约定生产入口验证要求覆盖的 crash → restart 恢复、拒绝或重复进入语义；helper-level GREEN 不能替代该证据。

实施失败本身不构成升档。只有证据表明测试接缝失真、机制假设错误、范围必须跨越新生产边界或失败空间不再有界时，报告 `DESIGN_EVENT` 与 `INCOMPLETE`；不要在实现中补写隐性设计。

## 返工

返工只处理消息列出的已接受 blocker：

1. 复现反例，或建立在返工前候选上失败的回归证据
2. 完成最小修复，不处理未派发的相邻问题
3. 重新证明受影响的父级验收条目
4. 运行约定的针对性门禁与生产边界验证
5. 报告每项 blocker 的关闭证据与返工增量

finding 若推翻设计假设、共享不变量、ownership 或状态机制，停止窄返工并报告 `DESIGN_EVENT` / `INCOMPLETE`。无关历史债务只记录为 nonblocking 观察，不顺手修复。

## 完成报告

证据齐全时报告 `READY_FOR_ACCEPTANCE`，并简要列出：

- 修改内容与文件范围
- 每项合同及对应证据
- RED、GREEN、针对性门禁与生产边界证据
- 实际 active elapsed 和护栏状态
- 未执行的独立审查与根门禁

`READY_FOR_ACCEPTANCE` 只表示候选证据已提交，由编排者决定是否接受。派发消息要求使用持久任务机制时，只有上述证据齐全才将其标记完成。

缺少影响正确性的证据、达到护栏或需要新权限/范围时报告 `INCOMPLETE`，列出已完成部分、缺失证据、未决假设和最小下一步。
