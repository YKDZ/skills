# C 类设计文档契约

只在被派发 C 类设计切片时读取。设计文档服务于一个共享机制，可被多个 ticket 引用；不要按 ticket 复制相同内容。

## 必须产出

1. **决策与范围**：要关闭的生产语义、适用 ticket、权威来源和非目标
2. **选定机制**：关键组件、ownership、资源生命周期、状态转移、接口与数据契约
3. **失败模式**：可达输入、并发、重入、部分失败、崩溃窗口、重试、恢复、权限和外部依赖；只覆盖当前范围可触发的路径
4. **不变量**：每条使用可判断的陈述，并说明在何处维护
5. **证明方式**：每个关键不变量对应生产接缝、反例、测试 oracle 或运行期观测
6. **假设与证据**：环境假设引用 `OBS-NNNN`；尚未验证的假设显式标记
7. **方案取舍**：选定方案为何足够；拒绝方案及拒绝原因。只记录会影响后续实现的选择
8. **实施边界**：实施者可自行决定的可逆细节，以及不得重新决定的单向门
9. **未决问题**：负责人和最小验证动作。会迫使实施者发明生产语义的问题存在时，设计状态为 `INCOMPLETE`

## 原型契约

只有派发消息明确允许原型时才填写，并在调用 `prototype` skill 前记录：

```text
PROTOTYPE-ID / 单一可证伪假设 / 静态证据为何不足 /
反证观察与判定阈值 / 将解锁的设计决策 /
允许操作与可写范围 / active-time 预算 / 停止条件 /
结果：supported|refuted|inconclusive / OBS 指针 / 设计决策回填
```

一次设计切片最多执行一个原型。首次获得决定性观察即停止；达到预算、越过范围、结果不确定或出现第二个待验证假设时报告 `INCOMPLETE`，不得扩大实验。

## 约束

- 不为 Spec 没有的需求设计，不进行投机性泛化或预留抽象
- 能用现有模式和因果测试关闭的问题不升级为 C
- 原型只用于契约中的单一假设；结论和复验命令进入 `docs/observations/`，原型代码不进入产品
- 文档应足以让 t1 实施者在不发明 ownership、状态或失败语义的情况下开始工作；不是逐文件施工说明

完成时给出 `READY_FOR_ACCEPTANCE` 或 `INCOMPLETE`，并列出每个未决假设。
