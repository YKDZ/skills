# 候选修复契约

只在消息列出已接受必修问题时读取。修复只关闭这些问题，不处理相邻意见。

1. 复现因果反例，或建立在修复前候选上失败的回归证据
2. 完成最小修复
3. 重新证明受影响的父级合同条目
4. 运行约定的针对性门禁与生产边界验证
5. 报告每项问题的关闭证据与修复增量

问题若推翻设计假设、共享不变量、所有权或状态机制，停止修复并报告设计事件与 `INCOMPLETE`。无关历史债务只记为观察。

已接受问题需要改变固定合同或生产接缝才能关闭、必要门禁需要消息未提供的外部条件，或修复必须越过可写范围时报告 `INCOMPLETE`，并保留已形成的关闭证据。固定边界内尚未关闭的问题继续当前 Goal。
