# 候选修复契约

修复派发消息中已确认的问题。沿代码查清受影响合同条目涉及的入口、调用方和状态路径，在既定授权内完成必要修改。

1. 复现原反例，保留其触发条件和预期结果；缺少可重放材料时先补齐
2. 完成最小修复
3. 从实际入口重新证明受影响的父级合同条目，覆盖原反例和应保持的正常行为
4. 运行约定的针对性门禁与生产边界验证
5. 报告已核对的受影响路径、每项问题的关闭证据与修复增量

问题若推翻设计假设、共享不变量、所有权或状态机制，停止修复并报告设计事件与 `INCOMPLETE`。无关历史债务只记为观察。

问题需要改变固定合同或生产接缝才能关闭、必要门禁需要消息未提供的外部条件，或修复必须越过可写范围时报告 `INCOMPLETE`，并保留已形成的关闭证据。固定边界内尚未关闭的问题继续当前 Goal。
