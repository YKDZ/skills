# 测试基础设施

为当前项目建立、改进或迁移测试基础设施，按用户请求设计方案或实施改动。优先复用项目已有工具，规模可以是一组夹具和命令，也可以是完整的平台。

同类测试使用仓库维护的入口，共用环境准备、就绪判断、超时处理、资源回收及相应的失败判定逻辑；各场景保留自己的输入、操作和断言。

## 原则

- **入口易用**：用项目惯用工具统一组织命令，明确各命令的职责，保持用法一致，并提供简明说明。说明每条命令的前置条件及其对环境生命周期的影响；常用流程可提供组合命令，复用相同实现。
- **职责独立**：业务代码不依赖测试设施，目录和包的划分按项目需要决定。
- **生产路径**：按验收范围选择生产模块或实际交付产物，通过稳定接缝验证。替换点位于被测范围之外，环境准备不能绕过本次要验证的行为。
- **依赖可选**：日常验证使用受控依赖和数据，按需显式启用真实外部服务。优先使用成本合适的真实实现；需要替身时，核对它与真实依赖的行为约定。
- **本地与持续集成一致**：同一验收范围共用执行逻辑和判定规则，通过配置或适配处理环境差异。声明依赖版本、测试输入及其获取方式，在同一组受控条件下复现结果；使用真实外部服务运行时，记录实际条件和验证范围。
- **隔离与重建**：隔离影响结果的测试状态，按需复用成本高的依赖。允许保留环境供连续运行或排查。明确资源归属和环境清理范围，确保失败或中断后仍可重新执行清理，并能按相同配置重建初始环境。
- **缓存复用**：优先使用工具链原生缓存，在多次运行间复用依赖和构建资源，减少重复下载与计算。遵循工具的校验、共享与失效规则；复用产物或结果时，核对影响其有效性的输入和环境。日常清理环境时保留可复用缓存，支持按需清除或绕过缓存，并能在缓存缺失时重建。命中缓存后，仍须保持既定的验证范围和判定标准。
- **快速反馈**：按风险与成本提供可单独运行的检查。从足以验证当前改动的较小范围开始，按需覆盖集成和真实外部依赖。
- **结果可信**：报告实际验证范围，区分通过、失败与未执行，并保留重试信息。清理前留存必要的失败证据和复现条件，供运行结束后定位问题。先观察被测行为，再回收剩余资源；回收成功不能掩盖产品失败。

## 改进既有设施

从现有入口核对调用关系和验证范围，根据实际问题确定本轮改动边界。迁移时保留原有的有效验证目标，并说明哪些部分仍由旧设施承担。新路径接管相关调用和验证后，移除已被替代的重复实现；必要的旧入口可转调共用实现。

优化反馈速度时，先测量耗时、找出瓶颈，兼顾总等待时间与累计计算成本，将环境准备、重复调用和重试计入其中。保持验证范围，在相同运行条件下复测，确认改动带来的改善稳定可靠。
